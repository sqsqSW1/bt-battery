# 蓝牙电量

在 Windows 11 任务栏的通知区域（时钟、音量、电池旁边）显示已经连上的蓝牙配件。每种设备一个小图标，大小接近系统音量、以太网；电池竖着叠在右下角。这样不用先按 `Win+A` 打开快速设置，再点「蓝牙」磁贴才能看到「已连接」。

程序名是**蓝牙电量**。界面、菜单和这份说明都是简体中文。平时不需要管理员。

## 你会看到什么

- 通知区域里始终有一个蓝牙符号，用来打开列表、设置和退出。设备都断开以后，也还能从这里退出程序。
- 每台已连接的鼠标、键盘、耳机（含耳塞、头戴）或手柄再各有一个图标。断开就消失，连上就出现。
- 设备图标尽量铺满托盘格子，和音量、以太网相近。电池竖着叠在右下角，盖在设备图标之上，用电量填充表示还剩多少。颜色跟随任务栏深浅。电量低于 20% 时电池改为空心，中间画一个感叹号，并用红色提醒。读不到电量时电池是空的，设备不会被藏起来。
- 鼠标停在图标上：设备名称、类型，以及百分比或「电量未知」。有多块电池时（例如左右耳）按较低的那块来画填充。
- 左键打开设备列表。右键是：刷新、设备列表、设置、退出。
- 设置里可以选开机启动、要显示的类型、读不到电量时是否还放图标、刷新间隔和图标颜色。

键鼠一体的设备会在勾选了鼠标或键盘时显示。手机、电脑、音箱默认不显示。

## 需要什么

- Windows 11（内部版本 22000 或更高），64 位。
- 自行编译时需要 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。直接运行已发布的轻量版只需系统自带的 .NET Framework 4.8 或更高版本。
- 用 Visual Studio 2022 也可以：打开 `BtBattery.sln`，启动项目选 `BtBattery.App`，平台选 x64。

蓝牙无线电要开着。程序只看本机已经配对并且当前连上的设备，不会去搜索周围的新设备。

## 编译和运行

在仓库根目录：

```powershell
dotnet test tests\BtBattery.Core.Tests\BtBattery.Core.Tests.csproj
dotnet run --project src\BtBattery.App\BtBattery.App.csproj -c Release
```

没有配件、只想先看图标和窗口时：

```powershell
dotnet run --project src\BtBattery.App\BtBattery.App.csproj -c Release -- --demo
```

`--demo` 会放四个示例图标（鼠标 85%、键盘电量未知、耳机 42%、手柄 12%），不读取这台电脑的蓝牙。

上面的 `dotnet test` 在 Windows 上会用同一组用例检查 .NET 8 核心库和轻量版 EXE。在其他系统上，它会检查跨平台的 .NET 8 核心库。带窗口的项目使用 WPF。

## 发布成一个 exe

### Windows 11 轻量版（小于 1 MB）

```powershell
.\publish.ps1 -Compact
```

程序位于 `artifacts\compact-win-x64\蓝牙电量.exe`。把这一个文件复制到 Windows 11 x64 电脑即可运行。它使用 Windows 内置的 .NET Framework 和蓝牙 API，复用同一套设备检测、托盘界面和设置代码。已有的 `settings.json` 可直接沿用。

### 自带 .NET 8 运行时的版本

直接运行 `publish.ps1` 会生成 **win-x64、自带运行时的单文件** `蓝牙电量.exe`。它把 .NET 8 和 WPF 一起打包，体积会到一百多 MB。

```powershell
.\publish.ps1
```

文件在：

```text
src\BtBattery.App\bin\Release\net8.0-windows10.0.22621.0\win-x64\publish\蓝牙电量.exe
```

如果这台电脑已经装了 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)，可以打一个小得多的版本：

```powershell
.\publish.ps1 -FrameworkDependent
```

单文件第一次启动会把本机库解出来，所以会稍慢一点。不要给发布命令加裁剪（`PublishTrimmed`），WPF 裁剪后容易在运行时缺类型。

## 开机启动

设置里勾选「登录 Windows 后自动启动」。程序写的是当前用户的注册表，不需要管理员：

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
数值名称：蓝牙电量
```

取消勾选会删掉这一项。每次启动时，如果设置里仍然开着自启，会把路径更新成现在的 exe，避免程序被移动以后启动项还指着旧位置。

从资源管理器或开始菜单启动的才是 exe 本身。用 `dotnet run` 时，自启会指向生成目录里的 `蓝牙电量.exe`，那个目录还在的话可以，发布后的 exe 更适合长期放着。

## 图标被收进「^」里

Windows 11 经常把新出现的通知区域图标收进时钟左边的向上箭头里，而不是直接放在音量旁边。这是系统的行为，程序不能替你改资源管理器。

1. 点任务栏右下角那个「^」。
2. 按住「蓝牙电量」，以及每个设备图标，拖到音量和时钟旁边。
3. 松手以后它们会留在那里。之后设备重新连接，图标一般还会出现在你拖过的位置；如果又被收进去，再拖一次即可。

Windows 11 没有一个可靠的开关能让第三方图标「始终显示在任务栏上」。拖出来是系统允许的做法。

## 第一次运行

- 用发布出来的 exe 或 `dotnet run` 都可以，不需要管理员。
- 如果 Windows 询问是否允许应用使用蓝牙，选允许。路径是：设置 → 隐私和安全性 → 蓝牙。关了的话，WinRT 那一层枚举会失败，程序仍会用经典蓝牙接口和即插即用属性继续工作。
- 打开快速设置（`Win+A`）不是必须的。那里的「已连接 (2)」只是说明系统自己也看到了两台设备。
- 设置和日志在 `%AppData%\蓝牙电量\`：`settings.json` 和 `log.txt`。设置窗口里的「复制诊断信息」会把每台设备的地址、类型来源、电量来源和实例 ID 放到剪贴板，方便对照设备管理器。这些内容只留在本机。

再启动一次程序会打开设备列表，不会开出第二个进程。

## 电量从哪来

和「设置 → 蓝牙和设备」一样，分三层，有数字就用，没有就试下一层。

1. **系统蓝牙电量属性** `DEVPKEY_Bluetooth_BatteryLevel`，键是 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2`，类型是一个 0–100 的字节。Windows 蓝牙协议栈会把下面这些来源写进这个属性，设置应用和 `Get-PnpDeviceProperty` 读的也是它：
   - BLE GATT 电池服务 `0x180F` / 特征 `0x2A19`
   - HID 电量报告（很多经典蓝牙鼠标、键盘）
   - 免提 HFP 电量（很多耳机）。这个值经常在「媒体 / 免提」节点上，不在名叫蓝牙的那个节点上。程序按蓝牙地址把这些节点并成一台设备，所以不会为同一个耳机画出三四个图标。
2. **Windows 电池接口** `Windows.Devices.Power.Battery`。能按地址或设备容器对上时才采用。有的设备这里还能看出是不是在充电。
3. **直接读 GATT `0x180F`**。只在前两层都没有数字时才读。每轮最多主动读取四台，优先尝试没读过的设备，再处理最久没读的设备。十分钟内复用同一台设备的缓存。读完就释放，不长期占着连接。未打包的桌面程序有时会被系统拒绝（没有包标识，也就没有 `bluetooth` 设备能力），诊断里会写「拒绝访问」，然后不再重试。仓库里的 `Package.appxmanifest` 只在你以后把程序打成 MSIX 时有用，平常的 exe 不会读它。

连接和断开靠设备树变化、WinRT 设备监视，再加上设置里的刷新间隔（默认 30 秒，可选 15 / 30 / 60 / 120 秒）。电量变化不一定会触发设备树消息，所以间隔刷新仍然需要。

### 仍然会显示「电量未知」的情况

这是配件和 Windows 之间没有电量数据，不是程序把图标弄丢了。

- 配件根本不通过 GATT、HID 电量报告或 HFP 上报。不少旧鼠标、一部分手柄属于这种。
- 厂商只用自己的应用和私有协议。AirPods 这类设备经常如此。程序不去拆这些私有广播，避免显示一个看起来精确、其实是猜出来的百分比。设置里能看到电量时，这里也应该能看到，因为读的是协议栈已经写好的那个属性。
- 耳机只建立了听歌用的音频连接，驱动没有把 HFP 电量写进设备属性。
- 蓝牙关着，或者设备只是配对了、当前没连上。没连上的设备不会出现在托盘里。

可以对照：打开「设置 → 蓝牙和设备」。那里没有百分比的设备，这里也会是「—」。

16×16 到 48×48（以及 125%、150%、200% 缩放）都用同一套布局：设备轮廓铺满格子，右下角是竖直电池。

## 目录

```text
src/BtBattery.Core        分类、地址、电量换算、设置文件。不依赖 Windows
src/BtBattery.App          WPF 托盘程序、图标、Win32 / WinRT 读取
tests/BtBattery.Core.Tests 上面那套纯逻辑的测试
publish.ps1                在 Windows 上打 win-x64 exe
```

设置文件损坏时会把原文件留成 `settings.json.bak`，然后用默认设置继续跑，避免托盘起不来。

## 隐私

程序不联网，也没有账号。设备名称、地址和电量只存在本机内存、本机日志和你主动复制的诊断文本里。日志超过大约 256 KB 会丢掉旧的一半。

## 已知限制

- 只能在 Windows 上编译和运行托盘程序。分类和换算的测试可以在其他系统上跑。
- 一台设备一个图标。左右耳的电量如果系统给了多份，按最低的一份来画填充，提示里会说明。
- 通知区域的位置由系统决定，见上面的「^」。
- 不修改资源管理器，不要求管理员，也不读取其他程序的窗口。
